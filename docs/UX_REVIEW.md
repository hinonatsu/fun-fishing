# UI・UXレビュー

実施日: 2026-10-30（日本時間）

## レビュー方法

- Chromiumの実画面を撮影し、視覚的な配置・読みやすさ・主要操作の到達性を確認する。
- 完全初心者、節約したい人、既に道具を持つ人、スマートフォン利用、途中で条件を変える人の操作を自動テストで模擬する。
- 自動テストでの模擬操作は、実在ユーザーへの調査ではない。

## 画面サイズ

360×800 / 390×844 / 768×1024 / 1280×800 / 1440×900 / 1920×1080。

## 発見・修正記録

開発中のChromium画面、IABでの実操作、自動検査、コードレビューで以下を発見し修正した。P2は主要操作の到達性・読みやすさ・状態の信頼性に影響する問題として扱った。

|重要度|発見した問題・条件|修正|回帰確認|
|---|---|---|---|
|P2|トップの補助文・番号、ビルダーの説明・番号、リストの進捗補助文が低コントラスト。axeで検出|対象の文字色を濃くした|4画面×PC/モバイルのaxe検査|
|P2|ブランドの音声操作名に、画面上の日本語キャプションが含まれていない|可視テキストを含む名前へ変更|axeのlabel-content-name-mismatch検査|
|P2|ビルダーの主要CTAが長い互換性説明の下になり、次の操作を見つけにくい|価格・主要CTAを互換性詳細より前へ移動|PC/モバイルの画面撮影、主要フロー|
|P2|共有URLのリストをリセット後、ブラウザで戻るとURL内の選択・チェックが復元されない|履歴の構成情報を読み直して状態を復元|共有→チェック変更→リセット→戻るのE2E|
|P2|型番不明の所持ロッドを登録しても、関連するリールが「推奨」に見える|関連カテゴリにも「要確認」を伝播|所持品の単体テスト、リールカードのE2E|
|P2|商品選択でパネルを閉じると、キーボードフォーカスが本文へ落ちる。IABで発見|パネルを開いた変更ボタンへ明示的に戻す|商品選択後にロッド変更ボタンがfocusedであることを確認|
|P2|モバイルメニューから案内を開いて閉じると、元の項目が非表示になりフォーカスが失われる。IABで発見|元の項目が非表示なら、可視のメニューボタンへ戻す|案内の閉じる操作・対応エリアのEscape後のfocusを確認|
|P2|共有ダイアログが左上へ寄る。モバイルIABで発見|CSS resetを考慮してmargin:autoを指定|PC/モバイルで共有ダイアログの中心座標を確認|
|P2|本文スキップのフラグメントが画面ルートと干渉し、現在の画面から移動する|URLを変えず本文へフォーカス|リストのURL・画面維持とmainフォーカスのE2E|

追加の耐障害対応として、港イラストの読込失敗時の代替表示、自動保存が使えないときの共有URL案内を実装。実ブラウザで失敗を注入し、リスト到達と共有導線を確認する。販売リンクの本文が未確認の商品は、仕様出典の中で検索掲載・JAN照合のみであることを説明する。

## 最終レビュー

最後のモバイルメニューのフォーカス修正後、同じ版に対して`npm run test:e2e -- --repeat-each=2`を実行した。38ケースを2反復し、合計76成功・0失敗・0スキップ（2.9分）。開発中にアプリが更新されたrunと意図的に中断したrunは、連続した最終レビューに含めていない。

|回|操作・自動検査|画面レビュー|
|---|---|---|
|1|38/38成功。PC/モバイルで主要フロー、異常系、focus、4画面axeを通過。6サイズ撮影・横はみ出し検査成功|トップ、魚/釣り方、ビルダー、商品パネル、非推奨状態、共有、対応データなしを確認。先の改善前画像と比べ、CTA到達性、配色、ダイアログ配置の改善を確認|
|2|同一版で38/38成功。前回と同じ対象を再実行し、再現可能な新しい不合格なし|更新されたPCトップ、モバイルのリスト/パネル/共有、タブレットのビルダーを再確認。主要操作を妨げる新しい重なり・はみ出しは見つからなかった|

上に記録したP2は対象の回帰確認を通過し、未解消のP0・P1・P2は本レビュー範囲では残っていない。改善余地が完全にないという評価や、実在ユーザーの使いやすさを証明したという評価ではない。Firefox/WebKit・実機・実ユーザー調査など、未検証の範囲は`QA_REPORT.md`に記載。
